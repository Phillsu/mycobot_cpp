# MyCobotDraw

用 C++ / Win32 寫的小工具：在一塊「小畫家」風格的白板上用滑鼠畫線，按下按鈕後
myCobot 360 M5 就會拿筆（或任何裝在夾爪上的畫具）把你畫的軌跡實際畫在紙上。
右半邊有一個內建的 **3D 模擬視圖**，會同步顯示機械臂目前的姿態、規劃路徑與實際
走過的軌跡；也可以完全不接機械臂，先在模擬裡把整張圖預跑一遍。

純 Win32 API + GDI（連 3D 繪圖都是自己算的投影，沒有用 OpenGL/DirectX），
沒有任何第三方函式庫依賴，用 Visual Studio 內建的 MSVC + CMake 就能編譯。

## 需求

- Windows + Visual Studio（含「使用 C++ 的傳統桌面開發」工作負載，內含 MSVC 與 CMake）
- myCobot 360 M5，官方原廠韌體（Atom / M5Stack-Basic），透過 USB 序列埠連接電腦
- 一支筆固定在夾爪 / 末端工具上，一張固定不動的紙

## 編譯

**方法一（推薦）：用 Visual Studio 開資料夾**
直接用 Visual Studio 開啟 `D:\RBT\mycobot_cpp` 這個資料夾（File → Open → Folder...），
VS 會自動偵測到 `CMakeLists.txt` 並幫你設定好，選擇 `MyCobotDraw.exe` 當啟動項目、
按 F5 或 Ctrl+F5 即可編譯執行。

**方法二：命令列**

```bash
cmake -S . -B build -G "Visual Studio 18 2026" -A x64
cmake --build build --config Release
```

（若你的 Visual Studio 版本不是 2026，把產生器名稱換成對應版本，例如
`"Visual Studio 17 2022"`；可用 `cmake --help` 查看目前機器支援哪些產生器。）

編譯完成後執行檔在 `build\Release\MyCobotDraw.exe`。

## 使用流程

1. **連線**：在裝置管理員確認 myCobot 對應的 COM Port 號碼，填入程式左上角，
   按「連線」。鮑率預設 `115200`（Atom 韌體標準值），一般不需更改。
2. **開啟馬達**：按「開啟馬達」讓機械臂進入可控制狀態。
3. **校正畫紙範圍（自由拖曳教導兩點）**：
   - 把紙固定好，紙的邊緣盡量與機械臂底座的 X/Y 軸方向對齊（因為目前用的是
     簡化的二點線性對應，沒有處理旋轉角度）。
   - 按「進入自由拖曳模式」→ 這會放鬆所有關節馬達（`release_all_servos`），
     此時可以直接用手把機械臂移動到任意位置。
   - 用手把筆尖移到**紙的左上角**、輕輕壓到紙面高度，按「記錄左上角 A」。
   - 再把筆尖移到**紙的右下角**、同樣壓到紙面高度，按「記錄右下角 B」。
   - 按「鎖定並離開拖曳模式」→ 程式會讀回目前角度並以低速重新鎖定，
     機械臂會停在原地不會突然彈動。
   - 抬筆高度、Z 座標、筆的朝向都是用 A、B 兩點的量測值算出來的
     （細節見下方「座標對應方式」）。
4. **設定繪製參數**：
   - 抬筆高度 (mm)：畫完一筆之後筆尖要抬高多少再移到下一筆的起點，預設 20mm。
   - 繪製速度 (1-100)：筆尖畫線時的速度，預設 30（保守值，可依實際狀況調高）。
   - 點間距 (mm)：畫布上的滑鼠軌跡會依此距離做取樣簡化，避免送出過多指令，預設 3mm。
5. **畫圖**：在白色畫布上用滑鼠畫線，可以畫多筆（分開的線段）。
   - 「清除畫布」：全部清空。
   - 「復原上一筆」：只刪掉最後一筆。
6. **先在 3D 模擬裡預跑（建議）**：勾選「模擬模式（不連機械臂）」後按下按鈕
   （此時按鈕會變成「在 3D 模擬中預覽」），右邊視圖就會用模擬的手臂把整張圖走一遍，
   完全不會送任何指令給真實機械臂。確認路徑合理、沒有紅色叉號（解不出姿態的點）
   之後，再取消勾選，正式送給機械臂。
7. **傳送至機械臂繪製**：機械臂會依序抬筆移動到每一筆的起點、下筆、沿著你畫的
   軌跡以直線插值 (`mode=1`) 逐點移動、畫完抬筆，直到所有筆畫完成。畫圖過程中
   畫布會鎖定，避免邊畫邊改。
8. **緊急停止 STOP**：任何時候都可以按，會立即送出停止指令並中止目前的繪製工作，
   最後仍會嘗試把筆抬起來，不會讓筆一直壓在紙上。

下方的日誌區會顯示每個動作的結果與錯誤訊息，方便除錯（例如連線失敗、逾時等）。

## 3D 模擬視圖

右半邊的視圖裡會畫出：

| 元素 | 說明 |
| --- | --- |
| 灰色網格 | 桌面（機械臂底座座標系的 Z=0 平面） |
| 紅／綠／藍軸 | 底座的 X／Y／Z 軸 |
| 淡黃色方框 | 你校正出來的畫紙範圍 |
| 藍色細線 | 規劃路徑（下筆段）；灰色虛線是抬筆移動段 |
| 紅色粗線 | **實際已經走過的軌跡** |
| 深灰骨架＋橘色關節 | 機械臂目前的姿態 |
| 紅色圓點 | 目前的筆尖（TCP）位置 |
| 紅色叉號 | 模擬時解不出可達姿態的點 |

操作：左鍵拖曳＝旋轉視角、右鍵拖曳＝平移、滾輪＝縮放、雙擊＝重設視角。

### 兩種同步來源

- **同步真實手臂姿態**（預設勾選，需先連線）：背景每 150ms 讀一次
  `GET_ANGLES` / `GET_COORDS`，把**真實量測到**的姿態與軌跡畫出來。校正完成後，
  程式會用筆尖高度是否低於紙面 +2mm 來判斷「這段是下筆還是抬筆」，
  所以紅線畫出來的就是機械臂真的畫在紙上的線。
  自由拖曳模式下也會同步，可以一邊用手扳動機械臂、一邊在畫面上看它動。
- **模擬模式（不連機械臂）**：完全離線，程式自己用逆運動學 (IK) 算出每個
  插值位置的關節角度，以接近真實速度播放整段路徑。

> 沒有機械臂也可以馬上試：按「載入示範校正（僅模擬）」→ 在左邊畫幾筆 →
> 勾選「模擬模式」→ 按「在 3D 模擬中預覽」。示範校正值只是為了讓你能離線把玩，
> 若在這個狀態下要送給真實機械臂，程式會先跳出警告要你確認。

### 運動學模型的精確度（請留意）

模擬用的連桿長度寫在 [src/Kinematics.h](src/Kinematics.h) 的 `kDefaultModel`，
目前用的是 320/360 級（350mm 臂展）的常見 DH 參數。**這組數字只影響「畫面上的
手臂長什麼樣子」**：

- 即時同步模式下，軌跡是機械臂韌體自己回報的 `GET_COORDS`，與這個模型無關；
- 模擬模式下，軌跡來自你的校正值與白板筆畫，也與這個模型無關；
- 只有「骨架的比例」和「模擬時算出的關節角度」會受它影響。

所以如果畫面上手臂的比例看起來和你的實機不一樣，改 `kDefaultModel` 即可，
不會影響實際畫圖的正確性。同理，模擬解出的手肘朝向不一定和實機韌體選的解相同
（實機是韌體自己解 IK），這在預覽用途上是可以接受的近似。

## 座標對應方式（重要，請理解後再使用）

目前採用**二點線性對應**，不解旋轉角度：

- 畫布像素 `(0,0)` → 對應 A 點的 `(x,y)`
- 畫布像素 `(canvasW,canvasH)` → 對應 B 點的 `(x,y)`
- 中間的點用線性內插
- 下筆高度 Z = A、B 兩點 Z 的平均值（假設紙是平的）
- 筆的姿態 (Rx,Ry,Rz) = A、B 兩點的平均值
- 抬筆時只是把 Z 加上你設定的抬筆高度，X/Y/Rx/Ry/Rz 不變

**限制**：如果紙沒有和機械臂底座的 X/Y 軸大致對齊，畫出來的圖形會有些微斜切
變形。這是刻意簡化的 MVP 設計，之後如果需要更精準，可以改成三點校正並解出
完整的仿射轉換（含旋轉），程式碼在 [src/Calibration.h](src/Calibration.h)
裡集中處理，之後要換算法只需要改這一個檔案。

## 安全注意事項

- 第一次使用請把繪製速度調低（例如 10~20），先看機械臂的實際行走路徑是否合理，
  確認沒問題再逐步調高。
- 校正時「記錄左上角/右下角」讀到的是**當下的實際座標**，如果手滑按錯位置，
  畫出來的圖會跑位但不會撞到超出機械臂可達範圍以外——不過建議校正時還是留意
  兩點別選在機械臂的可達邊界附近，避免繪製中因插值路徑而觸及限位。
- STOP 按鈕任何時候都可以按，且和背景執行緒的送指令是執行緒安全的
  （見 [src/MyCobotSerial.h](src/MyCobotSerial.h) 內部的 mutex）。
- 離開拖曳模式重新鎖定時用的是低速 (`SendAngles(angles, 20)`)，是為了避免
  馬達重新啟動torque時的瞬間彈動；仍建議手在旁邊扶著再放開。

## 通訊協定

程式內建的序列埠協定（`FE FE LEN CMD ...DATA... FA`，角度 ×100、座標 ×10 的
int16 大端序編碼）是依照 Elephant Robotics 官方開源函式庫
[pymycobot](https://github.com/elephantrobotics/pymycobot)（`pymycobot/common.py`
的 `ProtocolCode` 類別與 `pymycobot/generate.py` 的指令實作）逆向整理而來，
myCobot 360 M5 的 Atom 韌體原生就是說這套協定，不需要在機械臂端額外安裝任何
軟體。指令代碼定義集中在 [src/ProtocolCode.h](src/ProtocolCode.h)。

## 專案結構

```
src/
  main.cpp             程式進入點
  AppWindow.h/.cpp     主視窗：所有控制項、事件處理、流程整合
  Whiteboard.h/.cpp    白板畫布控制項（滑鼠畫線）
  SimView.h/.cpp       3D 模擬視圖（自己算投影的 GDI 繪圖）
  Kinematics.h/.cpp    正／逆運動學，只給模擬視圖用
  Calibration.h        二點校正 → 畫布座標轉機械臂座標
  PathPlan.h/.cpp      筆畫 → 路徑點（取樣簡化、抬筆/下筆），送出與預覽共用同一份
  MyCobotSerial.h/.cpp COM Port 通訊 + myCobot 協定封裝
  DrawingSender.h/.cpp 背景執行緒：實機逐點送出，或離線模擬播放
  AppMessages.h        自訂視窗訊息（跨執行緒回報進度／姿態／日誌）
  ProtocolCode.h       協定指令碼常數
```

## 已知限制 / 之後可以做的事

- 二點校正不處理旋轉，紙沒對齊底座軸向會有些微變形（見上方說明）。
- 目前是「送一點、等到位、送下一點」，繪製速度受限於每個點的等待時間；
  之後如果韌體的 fresh_mode/佇列功能穩定，可以改成連續送點以加快速度。
- 模擬用的 IK 是數值解（阻尼最小平方 + 多起點重試），只約束「筆尖位置」與
  「筆朝下」，不約束繞筆軸的旋轉；解出來的手肘朝向不保證和實機韌體一致。
- 「同步真實手臂姿態」每 150ms 會佔用一次序列埠往返，繪製中開著會讓每個點的
  節奏稍微變慢；想要最快的繪製速度可以在繪製前取消勾選（此時 3D 視圖會改用
  「已送出的指令座標」畫軌跡）。
- 沒有做筆畫的曲線平滑化（例如貝茲曲線擬合），純粹是取樣後直線連接，
  畫出來的線條在小點間距下已經相當平滑，但極細緻的曲線可能仍看得出多邊形感。
